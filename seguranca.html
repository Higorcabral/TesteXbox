Segurança

Segurança não é uma aba
do sistema. É como ele é construído.

Todo projeto que sai daqui segue a mesma arquitetura, independente do tamanho do cliente. Não existe versão simplificada para projeto pequeno, existe o mesmo padrão, com escopo menor.

01

Onde o código vive

Azure DevOps

Cada projeto tem repositório próprio, com histórico completo de quem mudou o quê e quando. Publicação acontece por esteira automatizada, não por alguém copiando arquivo para o servidor.

  • Histórico versionado, dá para voltar a qualquer ponto
  • Revisão antes de a mudança chegar em produção
  • Publicação automatizada, sempre pelo mesmo caminho
  • Nenhuma senha ou chave dentro do repositório
02

Onde a aplicação roda

Microsoft Azure

Recursos organizados por cliente, em grupo próprio. Isso é o que permite entregar tudo de um cliente (ou apagar tudo, no encerramento) numa operação só, sem sobrar recurso solto em lugar nenhum.

  • Um grupo de recursos por cliente, sem mistura
  • HTTPS obrigatório, com HSTS
  • Cabeçalhos de segurança aplicados na borda
  • Segredos em cofre, nunca no código
03

Onde os dados ficam

Supabase·Azure Database for PostgreSQL

Um banco por cliente. Nunca uma base compartilhada separada por coluna: basta um filtro esquecido para o dado de um cliente aparecer para outro, e isso vira questão de tempo.

  • Projeto de banco separado por cliente
  • Row Level Security ligada em toda tabela
  • Chave de serviço nunca exposta no navegador
  • Backup testado restaurando, não só exportando
04

Quem entra

Microsoft Entra ID

Identidade é a raiz de tudo: é por ela que se chega no código, na aplicação e no banco. Por isso conta é nominal, saber quem fez o quê depende disso.

  • Conta nominal, nunca login compartilhado
  • Verificação em duas etapas obrigatória
  • Menor privilégio: acesso de leitura quando leitura basta
  • Saiu do projeto, acesso removido no mesmo dia
O ponto que quase ninguém combina antes

As contas ficam no seu nome.

Domínio registrado no seu CNPJ. Assinatura e banco no seu nome quando o custo é seu. A Hifera entra como administradora, não como dona.

Isso importa no dia em que a relação acabar: você sai com tudo que é seu, sem depender de ninguém liberar nada. Quando alguma peça não puder ser separada, isso vai escrito na proposta, com o que acontece no encerramento. Nunca subentendido.

Dado pessoal

LGPD entra no escopo, por escrito.

Se o sistema vai guardar dado de pessoa física (seu cliente, seu paciente, seu funcionário), três perguntas são respondidas antes de a primeira linha de código existir.

Qual dadoO que exatamente é coletado, e por quê. O que não é necessário não entra.
Por quanto tempoPrazo de retenção definido, não "para sempre por padrão".
Quem pode verQuais papéis alcançam o dado, e o que acontece quando alguém sai.

O que a gente não promete

Não dizemos que é impossível alguma coisa dar errado, quem diz isso não trabalhou tempo suficiente com sistema em produção. O que dizemos é o que fazemos e como você confere.

Se em algum momento você quiser ver onde o seu dado está, quem tem acesso e quando foi o último backup restaurado com sucesso, a resposta existe e é sua. É só perguntar.
